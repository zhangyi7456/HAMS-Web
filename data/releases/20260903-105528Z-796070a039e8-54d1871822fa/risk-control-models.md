# 资产 V5 七资产风险封控模型解读

> FRAIS是“资产”内部风险引擎。本模型不自动交易，也不使用杠杆、做空或期权。

适用版本：产品 `4.1.0` / 策略 `1.2.0` / 配置 `3` / 公开契约 `4.0`。

## 1. 先看结论：模型分三次决定仓位

模型不会直接从风险分数跳到某只ETF。每个月末依次回答：

1. 全组合可以承担多少权益风险；
2. 权益预算中多少属于核心、多少属于卫星；
3. 每个组内部由哪些ETF承担，并执行组内上下限。

这三步把“风险总量”和“标的选择”分开，避免强势主题资产在相对强弱模型中反客为主。

## 3. 数据健康闸门

七只ETF的风险信号统一使用前复权日收盘价，并在公共交易日历上检查缺失、重复、零价、负价、异常跳变、数据过期和行情源错误。家庭实际份额估值另用未复权收盘价；两种价格字段、用途和测试严格分离。

任何阻断错误都会把状态切换为 `DATA ERROR`，保留上一份确认目标供阅读，但禁止形成新的人工买卖建议。系统不会用模拟价格替代缺失的真实行情。

## 4. 趋势、波动与回撤

每只ETF使用63、126、252日收益形成多周期趋势：

```text
TrendScore = 0.20 × sign(Return63)
           + 0.30 × sign(Return126)
           + 0.50 × sign(Return252)
```

波动评分使用20日与60日年化波动率：

```text
ForecastVol = 0.4 × Vol20 + 0.6 × Vol60
VolScore = min(1, 12% / ForecastVol)
```

回撤评分使用七资产固定战略组合参考NAV，而不是动态策略自己的NAV：

```text
Drawdown = StrategicNAV / High252 - 1
DDScore = clip(1 + Drawdown / 20%, 0, 1)
```

## 5. 全局风险评分与权益北极星

五只权益ETF的趋势评分先映射至 `[0,1]`，再按战略权益份额 `25/25/25/15/10` 合成趋势广度。

```text
R = 0.45 × TrendBreadth + 0.35 × VolScore + 0.20 × DDScore
TotalEquityTarget = 0.80 × (0.70 + 0.30 × R)
```

权益目标限制在56%—80%。这里的0.70叫“权益保留系数”，不是核心资产组比例。风险状态颜色只解释连续分数，不是额外买卖开关。

## 6. 核心—卫星分组预算

```text
CoreTarget = TotalEquityTarget × 75%
SatelliteTarget = TotalEquityTarget × 25%
DefenseTotal = 1 - TotalEquityTarget
```

分组预算固定，组间不因短期强弱转移资金。若权益目标为64%，则核心目标48%、卫星目标16%、防御目标36%。

## 7. 五权益相对强弱与组内配置

五只权益ETF在同一个横截面中计算：

```text
RelativeStrengthRaw = Return126 / Vol60
Attractiveness = exp(0.30×Trend + 0.15×RS - 0.15×VolPenalty)
```

RelativeStrength只标准化一次，再进入各自组内配置。禁止只在两只卫星ETF之间做极值映射。

核心组边界：510300、512890、513500各自组内25%—40%。

卫星组边界：513100组内50%—70%，588000组内30%—50%。

迭代式上下限归一化只在组内重新分配；核心合计必须等于核心预算，卫星合计必须等于卫星预算。

## 8. 防御资产配置

```text
GoldShareOfDefense = clip(
  0.35 + 0.12 × GoldTrend - 0.06 × BondTrend,
  0.20,
  0.45
)
```

黄金组合权重限制在4%—15%，国债限制在8%—35%，两者严格合计防御预算。

## 9. 双QDII溢价门控

513500 标普500ETF与513100 纳指ETF分别输入、分别判断：

| 人工溢价 | 该标的计划买入处理 |
| --- | --- |
| `<1.5%` | 正常 |
| `1.5%—3%` | 只执行50% |
| `≥3%` | 禁止新增 |
| `≥5%` | 显示红色警告，仍不主动卖出 |

被拦截资金临时转入511010 国债ETF。门控只改变人工执行建议，不改变风险评分和模型目标。

## 10. 调仓节奏与无未来函数

日频数据只更新观察指标，周频页面用于家庭复核，正式目标只在月末确认：

```text
Close T 计算月末信号
→ 最早T+1供人工使用
→ 回测在Close T+1成交并扣费
→ 新仓位从T+2收益开始贡献
```

普通调仓采用 `max(1个百分点, 15%×目标权重)` 的免交易带。越过边界后只修复目标缺口的50%，并受现金和自融资约束。

V5把“月末已确认”和“确认目标已到首个可用日”同时放入浏览器计算闸门。即使页面能够读取日频或周频状态，只要任一条件不满足，所有建议金额仍归零。

## 11. 家庭使用边界

页面提供风险状态、目标配置、真实市场证据、当前持仓偏差和人工再平衡建议。模型确认目标是唯一目标口径；执行规则只决定是否行动，不二次改写风险模型目标。

本版本不连接券商、不提交订单、不预测未来价格。当前持仓、现金流、资产历史和人工溢价仅保存在本机浏览器；公开GitHub数据不包含家庭私人资产信息。

## 12. 家庭资产账本与收益口径

家庭资产曲线从用户第一次确认持仓的日期开始，不根据当前权重反推过去。新增资金和取出资金从投资收益中剔除：

```text
DailyReturn[T] = (TotalAssets[T] - ExternalCashFlow[T]) / TotalAssets[T-1] - 1
PerformanceNAV[T] = PerformanceNAV[T-1] × (1 + DailyReturn[T])
```

份额模式用未复权收盘价估值；市值模式保留用户确认值并把日频延伸标成估算。只有一个记录点时不显示收益率。页面用“已确认资产记录 / 估算，需核对 / 暂无法计算收益”明确披露质量，不用战略参考NAV或回测NAV冒充家庭真实收益。

家庭当前回撤和最大回撤只从上述现金流中性净值计算。误录的外部现金流允许作废，但原记录、更正编号和时间仍保存在本机审计账本中，不覆盖历史。

## 13. V5运行时完整性审计

页面启动时会重新核对六项关系：ETF目标合计100%、权益ETF合计等于风险引擎权益目标、核心/卫星/防御预算守恒、每只ETF满足对应上下限、月末确认与T+1时序成立，以及公开决策哈希链完整。任一项失败都会关闭新建议闸门。

生产发布还必须通过跨数据源一致性、双QDII边界、旧持仓/旧备份迁移、参数敏感性、隐私扫描及桌面/手机验收。评价顺序固定为：正确性、无未来函数、可解释性、稳健性、最大回撤控制、换手控制、CAGR。

## 14. 组合范围与现金口径

系统不再通过家庭资产边界问卷、权益上限或风险承受问题二次改写模型目标，也不据此给出个性化投资适当性结论。组合范围由用户实际录入的七只ETF和组合内现金直接界定。

录入“组合内现金”即代表这笔现金可以参与本期人工调仓的现金可行性求解。应急备用金、未来确定支出和其他不希望参与投资的资金必须留在本账本之外。旧备份中的IPS与资金桶字段只为兼容读取而保留，不再进入校验或建议门控。

未来计划投入不属于已到账现金，仍不能进入当前总资产或本期买入预算。模型确认目标是唯一目标口径，执行层只通过数据健康、持仓时效、月末确认、T+1、免交易带、部分再平衡、整手、现金和QDII溢价约束决定是否形成建议。

## 15. 连续建议与可执行建议

系统先计算连续目标缺口，再按以下顺序转换为人工可执行数量：

1. 按ETF整手向零取整；
2. 卖出数量不超过本机记录的可用份额；
3. 计入配置的单边交易成本；
4. 买入金额不得超过组合内现金与卖出净所得；
5. 若资金不足，优先移除相对目标偏离较小的买入整手。

页面同时保留理论计划、整手后数量、估算成本、计划后现金和剩余偏离。它们是复核材料，不是券商订单。

## 16. 只追加建议与决策链

本机建议保存后不会改变持仓，只产生一条`UNEXECUTED`记录；家庭可以继续追加“部分执行、已执行、跳过”状态，旧状态不覆盖。QDII暂缓资金按标的独立留痕，下一个月末按新目标重新计算，不自动追补。

公开月末决策记录包含策略版本、配置指纹、输入区间、输入指纹、上一条哈希和本条哈希。已经发布的历史决策若被静默修改，刷新会发布阻断心跳，而不是覆盖旧结论。
